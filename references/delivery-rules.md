# User-selected delivery

Ask only for missing information affecting saving: chat-only, local file or connected document. Reuse confirmed destinations and permissions. Do not assume DingTalk, an account or a path.

- Chat-only: return content without automatically creating files or external documents.
- Local: use the chosen directory and format. Markdown is a portable fallback when no rich format is requested. Use available DOCX/PDF tooling and its required verification for those formats. Follow workspace rules and keep task materials outside skill directories.
- Online: use the user's platform, available connector and required workflow. DingTalk, Notion, Google Docs, Microsoft 365 and others are possible destinations, not integrations bundled here. Do not install connectors or switch platforms without authorization.

JD, interview questions and candidate records may have separate destinations. Do not reuse a previous role's documents for a new role unless instructed.

Read targets first. Preserve existing content, structure, styles, attachments and numbering. Default to H1 candidate sections with score in the name; supplements can be H3 within the entry. Match the user's existing format. Append new candidates once and update existing ones when new evidence arrives; preserve sources and explain score changes.

After saving, read back to verify content and destination. Inspect current state before retrying a failed or timed-out write to prevent duplicates; follow connector retry limits. Report partial/failed delivery honestly. If online access is unavailable, finish the content in chat; save a local alternative only if authorized, and never describe it as a successful online update.

Keep private mappings and preferences in permitted task notes or memory, outside the distributable skill. Reconfirm only a materially changed destination or destructive operation whose authority is missing.
